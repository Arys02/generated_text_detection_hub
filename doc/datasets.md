# Datasets

Two datasets are registered in `src/data/dataset_factory.py`: `aprdb` and `sem_detect`. A third module, `src/data/dataset_openturingbench.py`, is not in the factory (see section 4). Every dataset is a `torch.utils.data.Dataset` whose items are dictionaries; the evaluation contract (`content`, `label`, `review-id`) is described in `doc/architecture.md`, section 4.

## 1. APRDB (`aprdb`)

Source: Hugging Face `IntelLabs/AI-Peer-Review-Detection-Benchmark` (card summary in `doc/dataset/ai-peer-review-detection-benchmark.md`). Config: `conf/dataset/aprdb.yaml`. Class: `AprdbDataset`.

How it is built (`dataset_aprdb.py`):

1. `list_repo_files` lists the CSV files of the chosen `split` (`calibration`, `test` or `extended` subfolder of the repository; a list of splits is accepted); file paths look like `test/gpt4o/ICLR2022.test.gpt-4o.csv`, from which the generator, conference (`ICLR`/`NeurIPS`) and year are parsed. This needs network access on a cache miss, and **no `revision` is pinned**, so the content may change upstream (audit anomaly A22).
2. Files are filtered by `conference` and `date`. When `date` is `null` the loader uses the default list `["2016", "2017", "2018", "2019", "2020", "2021"]` (see the code), so years after 2021 are excluded unless `date` is set explicitly.
3. Each file is downloaded with `hf_hub_download` and read as CSV. `content` is the `review` column, or `main_review` when `review` is empty. With `keep_meta: true` the columns `subset`, `generator`, `conference`, `year`, `file`, `PaperId`, `review-id` are kept next to `label` and `content`.
4. With `with_pdf: true`, PDF paths are attached (`_attach_pdf_paths_local`, see `cristal_anchor.md`); reviews without a local PDF are filtered out.
5. With `subset_size`, half of the label-1 rows and half of the label-0 rows are drawn after a shuffle seeded by `seed` (an integer is required when `subset_size` is set), then the union is shuffled.
6. Afterwards, duplicated `content` values are dropped (`FilterDataCleaning(no_duplicate=True)`, always on by default; it is not a YAML key). Because this happens after the draw, the final size can be below `subset_size`.
7. The result is cached with `torch.save` as `CACHE_DIR/dataset_cache/dataset_<hash>.pt`, where `<hash>` is the MD5 of the dataset config (`get_hash()`). A cached file is loaded with `torch.load(..., weights_only=False)`.

Config keys (`conf/dataset/aprdb.yaml`): `name`, `description`, `conference`, `date`, `keep_meta`, `subset_size` (100 by default), `split` (`test`), `with_pdf`, `seed` (`0`). The `seed` was `${seed}` (42) before 2026-10-15 and is now the literal `0`; this changes the sample drawn and the hashes of old runs (audit anomaly A14). To recompute old hashes try `dataset.seed=42` (not verified by running).

Labels: `1` machine-generated, `0` human (project interpretation, anomaly A30).

## 2. Sem-Detect (`sem_detect`)

Source: Hugging Face `Sem-Detect/ML_Conferences-Peer-Reviews` (Duarte et al., arXiv 2605.21713), ICLR and NeurIPS 2021-2022, classes `human`, `rewrite` (LLM-refined) and `ai`; AI reviews generated by Gemini 2.5 (flash and pro), DeepSeek v3 and Qwen3-235B. Config: `conf/dataset/sem_detect.yaml`, with the revision pinned to `18b74b551670bff6b04e57570232a1694997863b`. Class: `SemDetectDataset` (`dataset_semdetect.py`, loader version 3).

Items contain at least `content` (the cleaned review), `label` (depends on `label_mode`), `label_3c` (0 human, 1 rewrite, 2 ai) and a unique `review-id`; with `keep_meta: true`, `source-review-id` links an AI review to the human review it was generated from.

| Key | Values | Meaning |
|---|---|---|
| `split` | `train`, `test`, `val` or a list | `val` is virtual: a fraction of the training papers (`val_fraction`, `val_seed`) |
| `conference`, `date`, `generator` | `null` or subsets | `generator` filters AI/rewrite reviews; human reviews are always kept |
| `label_mode` | `human_vs_ai` (rewrite excluded), `ai_vs_rest`, `human_vs_llm`, `three_class` | how `label` is derived from the class |
| `balance` | `uniform`, `none`, `paired` | `paired` matches AI and human reviews on paper and rating; it balances the real classes (`label_3c`), not `label`, so binary labels can be 2:1 in some modes |
| `subset_size`, `seed` | integer / `null`, integer | `uniform` and `none` sample with pandas `random_state=seed`; the virtual `val` split and `paired` use stable MD5-based choices (independent of `PYTHONHASHSEED`). `uniform` balances by `label`, `paired` by `label_3c` |
| `no_duplicate`, `keep_meta`, `keep_claims`, `with_paper` | booleans | `with_paper` adds `paper_content`, `paper_appendix`, `forum_id` but **not** `pdf_path` |
| `exclude_ids_path` | path or `null` | list of ids to exclude; its digest enters the cache key |
| `revision`, `repo_id` | strings | pinned Hugging Face revision |

The same cache mechanism as APRDB applies (`CACHE_DIR/dataset_cache/dataset_<hash>.pt`, hash over the config plus the loader version, tokenizer and exclusion digest). The SAGE trainer skips `pair_and_balance` when `balance == "paired"`.

## 3. Using a dataset in the three entry points

- Evaluation: `dataset_factory(cfg.dataset)` then `data_loader(cfg.data_loader, ds)`.
- SAGE training: `dataset_train` and `dataset_val` go through the same factory; the dataset must implement `get_hash()`, `get_config()` and `to_pandas()` because the segmentation caches its output by `get_hash()`.
- Adding a dataset: see `doc/extending.md`, section 3.

## 4. Other data

- `src/data/dataset_openturingbench.py`: OpenTuringBench loader, not in the factory; it depends on `DATA_HWT_PATH`, which `src/config.py` no longer defines, so it is broken (audit anomaly A6). `run_eval.py` still imports it.
- `data/`: APRDB preparation notebooks (`data/ai-peer-review-detection-benchmark/`). The former Kaggle news files and the OpenTuringBench downloader notebook were removed before publication (unused by the factories).
- `src/detector/sem_detect/` caches: claims, embeddings and local reference reviews produced by the notebooks (see `doc/detector/sem_detect.md`).
