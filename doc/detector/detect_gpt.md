# DetectGPT

Perturbation-based zero-shot detector: a text generated by a model sits near a local maximum of that model's log-likelihood, so perturbed versions of it have a clearly lower log-likelihood than the original.

- Code: `src/detector/detect_gpt.py` (class `DetectGPT`); config `conf/detector/detect_gpt.yaml`; detector name `detect_gpt`, type `statistical`.
- Provenance: according to the project author, ported from the Ada-DetectGPT repository (https://github.com/Mamba413/AdaDetectGPT; Zhou et al., NeurIPS 2025, arXiv 2510.01268). That repository states that its baseline detectors are modified from their official versions or from the Fast-DetectGPT repository, and showed no licence file when consulted on 2026-10-20 (to be re-checked; audit anomaly A28).

## How it works (`predict`)

For each text (truncated to its first 300 words):

1. Build `n` perturbed copies: `tokenize_and_mask` replaces random spans of `span_length` words (the number of spans is `pct_words_masked * n_words / (span_length + 2)`, so with 0.3 and spans of 2 words about 15 % of the words are masked) with `<extra_id_k>` markers; a T5 mask-filling model generates the fills (`replace_masks`, `extract_fills`, `apply_extracted_fills`); empty results are retried. Perturbation runs by chunks of 10 texts.
2. Score the original and the perturbed texts with the scoring causal LM: `get_ll` is the negative mean token loss.
3. `z = (ll_original - mean(ll_perturbed)) / std(ll_perturbed)` (the standard deviation is replaced by 1e-8 only when it is exactly 0), and the returned score is `sigmoid(z)`. Higher means more likely machine-generated.

The class also contains offline helpers (`generate_perturbs`, `save_data`, `load_data`) that read and write `*.raw_data.json` files; the evaluator does not use them.

## Parameters (`conf/detector/detect_gpt.yaml`)

| Key | YAML value | Notes |
|---|---|---|
| `scoring_model_name` | `gpt2-xl` | scoring LM |
| `mask_filling_model_name` | `t5-3b` | T5 loaded with `AutoModelForSeq2SeqLM` |
| `pct_words_masked` | 0.3 | fraction of words masked |
| `span_length` | 2 | words per masked span |
| `mask_top_p` | 1.0 | nucleus sampling of the mask filler |
| `n_perturbation` | 100 | **not read**: see below |
| `device` | not in the YAML | taken from `params.device`, else `cuda` if available. The preset's `hardware.device` does **not** feed it (it is not interpolated into `detector.params`), so the preset's `cuda:0` does not select the GPU |

**Config mismatch.** The code reads `n_perturbations` (plural) with a default of 10 (`self.config.get('n_perturbations', 10)`), while the YAML defines `n_perturbation` (singular, 100). The YAML value is never used: the evaluator runs 10 perturbations per text. Any published number obtained with this preset used 10 perturbations unless the key was overridden. (`generate_perturbs`, which is not used by the evaluator, reads the plural key `args.n_perturbations`.)

Models are loaded from `CACHE_DIR/local.<model_name with / replaced by _>` if that directory exists, otherwise from the Hugging Face hub with `cache_dir=CACHE_DIR`. Sampling is not seeded (`np.random.randint` and the mask model's sampling use the global state), so scores are not reproducible run to run.

## Preset and running

`conf/experiment/eval/detect_gpt_simple.yaml` (APRDB, `hardware: single_gpu`). Its `name` is `detect_gpt_gpu1`; `fast_detect_gpt_simple.yaml` carries the same `name` (audit anomaly A2).

```bash
python -m src.evaluation.run_eval experiment/eval=detect_gpt_simple
```

Cost: `n` mask-filling generations and `n + 1` scoring passes per review; this is the slowest of the statistical baselines.
